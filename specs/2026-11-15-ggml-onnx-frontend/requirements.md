# GGML ONNX-subset frontend — requirements

**Date:** 2026-11-15
**Branch:** `feature/ggml-yolo-family` (working tree)
**Status:** First slice implemented and tested; RT-DETR still blocked
**Program:** neuriplo-infer `2026-11-13-ggml-matrix-coverage` Phase 2, Stage 1

## Goal

Import a static-shape ONNX subset into `ggml_graph::Graph` so transformer
models can execute without another hand-written `GGMLInfer` topology. Tiny
fixtures prove the frontend contract first; a fixed-batch `rtdetrv4.onnx`
probe drives the next op additions.

## In Scope

- `backends/ggml/src/GGMLOnnx.{hpp,cpp}`:
  - self-contained ONNX protobuf reader (no protobuf/ONNX C++ dependency);
  - static rank 1..4 shapes, FLOAT/DOUBLE/FLOAT16, INT32/INT64 tensors;
  - graph inputs with FLOAT/INT32/INT64, multiple inputs and outputs;
  - ops: Add, Sub, Mul, Div, Sqrt, Clip, Conv, depthwise Conv, MaxPool,
    MatMul, Gemm, Relu, Sigmoid, Softmax, LayerNormalization, Gather,
    Reshape, Transpose, Concat, Squeeze, Unsqueeze, Flatten, Cast, Identity,
    Constant, ConstantOfShape, Shape;
  - fail loudly on unsupported ops, dynamic shapes, external data, sparse
    initializers and unsupported broadcast direction.
- `backends/ggml/test/GGMLOnnxTest.cpp` plus checked-in fixtures generated by
  `backends/ggml/test/generate_onnx_fixtures.py`.
- CMake wiring into `libneuriplo.so` and the GGML test binary.

## Out of Scope

- Dynamic batch/symbolic shapes.
- `Slice`, `ReduceMean`, `ReduceSum`, `ReduceMax`, `Pow`, `Abs`, `Log`,
  `Erf`, `Pad`, `Resize`, `Split`, `Expand`, `Tile`, `TopK`,
  `GatherElements`, `GridSample`.
- Full `rtdetrv4` raw parity and the `rtdetr` app gate.
- Replacing `GGMLInfer`'s ResNet/YOLO paths.

## Decisions

- [D-1] Parse ONNX wire format directly. A protobuf/ONNX C++ dependency would
  add toolchain and ABI surface to the GGML backend for a small subset.
- [D-2] Keep ONNX shapes in ONNX order in the frontend and reverse axes only
  at the `GGMLGraph` boundary, matching `GGMLInfer`'s NCHW convention.
- [D-3] Lower MatMul/Gemm to `Op::Linear` with an arranged weight so the
  result keeps ONNX layout and does not need a post-matmul transpose.
- [D-4] Narrow INT64 constants to INT32; cast INT64 graph inputs on the host
  because the installed ggml cast kernel aborts on I64→I32.
- [D-5] Use `ggml_conv_2d_dw_direct` for depthwise conv. `ggml_conv_2d_dw`
  asserts that the kernel is F16 on this CPU build.
- [D-6] Unsupported constructs are hard errors. Silent fallback would make
  matrix evidence untrustworthy.
- [D-7] ONNX `Erf` stays unsupported: this ggml build has `ggml_gelu_erf` but
  no standalone erf op, and emulating it with a polynomial is not justified
  before an RT-DETR parity gate.

## Requirements

- [R-1] Multi-input FLOAT graphs execute with exact input blob validation.
- [R-2] INT64 graph inputs can drive Gather through the host cast.
- [R-3] Gemm/MatMul/Transpose/Softmax/Sqrt/Div form a correct attention block.
- [R-4] Conv, depthwise Conv, bias, and MaxPool match ONNX reference outputs.
- [R-5] Shape/activation ops (Reshape, Concat, Squeeze, Unsqueeze, Relu,
  Sigmoid, ConstantOfShape) match ONNX reference outputs.
- [R-6] Unsupported ops and dynamic shapes fail with actionable messages.
- [R-7] Existing GGML ResNet/YOLO/YOLO-seg tests stay green.
