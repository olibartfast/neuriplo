# GGML ONNX-subset frontend — requirements

**Date:** 2026-11-15
**Branch:** `feature/ggml-yolo-family` (working tree)
**Status:** Frontend green through the transformer decoder; rank-5 tensors block RT-DETR
**Program:** neuriplo-infer `2026-11-13-ggml-matrix-coverage` Phase 2, Stage 1

## Goal

Import a static-shape ONNX subset into `ggml_graph::Graph` so transformer
models can execute without another hand-written `GGMLInfer` topology. Tiny
fixtures prove the frontend contract first; a fixed-batch `rtdetrv4.onnx`
probe drives the next op additions.

## In Scope

- `backends/ggml/src/GGMLOnnx.{hpp,cpp}`:
  - self-contained ONNX protobuf reader (no protobuf/ONNX C++ dependency);
  - static shapes, FLOAT/DOUBLE/FLOAT16, INT32/INT64 tensors;
  - graph inputs with FLOAT/INT32/INT64, multiple inputs and outputs;
  - ops: Add, Sub, Mul, Div, Sqrt, Clip, Pow (exponent 1/2/0.5), Conv,
    depthwise Conv, MaxPool, MatMul (rank 2, rank-1 and batched), Gemm,
    integer Add/Sub/Mul/Div, Relu, Sigmoid, Abs, Log, Erf, Softmax,
    LayerNormalization, Gather, GatherElements, GridSample, Reshape,
    Transpose, Concat, Slice, Split, Squeeze, Unsqueeze, Flatten, Cast,
    Identity, Constant, ConstantOfShape, Shape, ReduceMean, ReduceSum,
    ReduceMax, TopK, Pad, Resize, Expand, Tile;
  - constant folding for INT64/FLOAT shape subgraphs and broadcast repeats;
  - fail loudly on unsupported ops, dynamic shapes, external data, sparse
    initializers and unsupported broadcast direction.
- `backends/ggml/test/GGMLOnnxTest.cpp` plus checked-in fixtures generated by
  `backends/ggml/test/generate_onnx_fixtures.py`.
- CMake wiring into `libneuriplo.so` and the GGML test binary.

## Out of Scope

- Dynamic batch/symbolic shapes.
- Rank-5 tensors with non-singleton leading axes. The frontend drops leading
  singleton axes because ggml is 4-D and tracks the axis offset; other rank-5
  layouts fail loudly.
- The `rtdetr` app gate and app-level output mapping.
- Replacing `GGMLInfer`'s ResNet/YOLO paths.

## Decisions

- [D-1] Parse ONNX wire format directly. A protobuf/ONNX C++ dependency would
  add toolchain and ABI surface to the GGML backend for a small subset.
- [D-2] Keep ONNX shapes in ONNX order in the frontend and reverse axes only
  at the `GGMLGraph` boundary, matching `GGMLInfer`'s NCHW convention.
- [D-3] Lower MatMul/Gemm to `Op::Linear` with an arranged weight so the
  result keeps ONNX layout. Batched MatMul chooses between
  `BatchedMatMul`/`BatchedMatMulTransposed` from the ggml broadcast direction.
- [D-4] Narrow INT64 constants to INT32; cast INT64 graph inputs on the host
  because the installed ggml cast kernel aborts on I64→I32.
- [D-5] Use `ggml_conv_2d_dw_direct` for depthwise conv. `ggml_conv_2d_dw`
  asserts that the kernel is F16 on this CPU build.
- [D-6] Unsupported constructs are hard errors. Silent fallback would make
  matrix evidence untrustworthy.
- [D-7] Implement ONNX `Erf` with `ggml_map_custom1` and `std::erf`; this
  ggml build has no standalone erf op. The callback is host-only.
- [D-8] `TopK` values/indices are computed per row for the last axis. They are
  not sorted to ONNX `sorted=1` order; near-tie order can differ from ORT.
- [D-9] `GatherElements` uses a host `ggml_map_custom3` callback for ONNX
  axis 1 only.
- [D-10] `Pad` supports end padding only; non-zero begin padding is rejected.
- [D-11] Leading singleton axes are dropped for ggml's 4-D limit, with an
  explicit axis offset. Ops that would move a dropped axis into the graph fail
  loudly.
- [D-12] `GridSample` is a host bilinear callback (zeros padding,
  align_corners 0/1), matching the RT-DETR deformable-attention use.
- [D-13] Integer shape arithmetic uses a host I32/I64 callback; integer
  operands are narrowed to I32 before repeat.

## Requirements

- [R-1] Multi-input FLOAT graphs execute with exact input blob validation.
- [R-2] INT64 graph inputs can drive Gather through the host cast.
- [R-3] Gemm/MatMul/Transpose/Softmax/Sqrt/Div form a correct attention block.
- [R-4] Conv, depthwise Conv, bias, and MaxPool match ONNX reference outputs.
- [R-5] Shape/activation ops (Reshape, Concat, Squeeze, Unsqueeze, Relu,
  Sigmoid, ConstantOfShape) match ONNX reference outputs.
- [R-6] Unsupported ops and dynamic shapes fail with actionable messages.
- [R-7] Existing GGML ResNet/YOLO/YOLO-seg tests stay green.
- [R-8] Shape-subgraph folding (Shape/Slice/Gather/Concat/Reshape) matches
  the source shape without a runtime dependency on the shape values.
- [R-9] Slice (step 1 and full axis-0 reverse), Split, Expand, Tile, Pad,
  Resize-nearest, and ReduceMean/Sum/Max match ONNX reference outputs.
- [R-10] TopK and GatherElements match the ONNX reference for the supported
  batch/axis cases.
- [R-11] Erf matches `std::erf`/ONNX within 1e-6.
- [R-12] GridSample bilinear matches the ONNX reference on the unit fixture.
- [R-13] Fixed-input `rtdetrv4` raw parity matches ORT by label and box for
  all 300 detections; near-tie index order may differ.
