# GGML real loader (ResNet18 classify) — requirements

**Date:** 2026-11-13
**Branch:** `feature/ggml-real-loader` from `develop`
**Status:** Specified, not implemented
**Cross-repo packet:** neuriplo (this packet, real fix) + neuriplo-infer
(`feature/ggml-matrix-coverage` docs column + wiring probe, no semantics change)

## Goal

Run the full ResNet18 graph through GGML with ORT parity, proving the GGML
backend can carry a real model the way the other backends do. Input is the
same `resnet18.ggml` artifact (`resnet18-v1-7.onnx` → converter, all 102
float initializers carried). The loader builds the genuine topology —
conv stem, 8 residual blocks with skips, global average pool, FC head —
from real weights, and the golden test asserts parity against an ORT
reference (same input, top-5 agreement + bounded max-abs-diff).

Model facts (verified from `/tmp/resnet18-v1-7.onnx`): 20 Conv, 20
BatchNormalization (uniform epsilon 1e-5), 17 Relu, 1 MaxPool, 8 Adds,
1 GlobalAveragePool, 1 Flatten, 1 Gemm (transB=1). 102 initializers.

Scope note (Phase 1, done): the merged head-only gate (pool + real FC) was
the honest stepping stone; this phase replaces its graph with the full
topology. Conv/BN now execute; no ORT parity claim is waived anymore —
parity is the exit criterion (see [Q-2]).

## Decisions (appended Phase 2)

- [D-6] Full ResNet18 topology is hardcoded in the loader (per-model graph
  builders, like the task-specific wiring in other backends). A general
  topology-driven executor is a later phase; one passing model first.
- [D-7] BatchNorm folding is exact for frozen inference: at load, per-channel
  `s = w/sqrt(var+eps)`, `beta = b - mean*s` (eps = 1e-5, verified uniform
  in the model file). No BN op needed in-graph.
- [D-8] Layout conversion happens once per tensor at load (ONNX row-major
  `[O,I,H,W]` → ggml `[KW,KH,IC,OC]`; input NCHW blob → `[W,H,C,N]` order at
  inference). No per-op transposes in the graph.
- [D-9] ORT reference is generated by stock `onnxruntime` (venv, pinned in
  validation evidence), never shipped. Parity target: top-5 class agreement
  + max-abs-logit-diff recorded, tolerance adopted from measurement
  (proposal: ≤1e-3).

## In Scope

- `backends/ggml/src/GGMLInfer.cpp/.hpp`: parse real model bytes, build a real
  graph, return real outputs.
- `scripts/convert_onnx_to_ggml.py` + `docker/Dockerfile.ggml` model stage:
  emit a loadable weight file (or document exact byte layout the loader expects).
- `backends/ggml/test/GGMLInferTest.cpp`: golden (non-zero, finite, deterministic)
  + negative tests (missing file, bad size, multi-input).
- `docs/backends.yaml` + generated docs if the model format/source text changes.

## Out of Scope

- Generic GGUF architectures (Gemma/VLM stay on `LLAMACPP`; no `llama.cpp` change).
- Dynamic shapes / batch>1 / other models. Fixed `1x3x224x224 → 1000` only.
- GPU/CUDA path. `FORCE_GPU 0` stays; `use_gpu=true` becomes an error (see D-2).
- Public C++ API, consumer C ABI, plugin ABI, other backends, version bumps
  beyond what the probe proves necessary (`GGML_VERSION` stays `v0.11.0` unless
  headers lack a needed symbol).

## Decisions

- [D-1] ResNet18-classify first. The Dockerfile model stage already standardizes
  on it; a generic GGUF loader is a separate phase.
- [D-2] `use_gpu=true` fails fast with an actionable error instead of the current
  silent CPU fallback (`GGMLInfer.cpp:62-66`). Roadmap Phase 3 owns device
  semantics; silent substitution is banned.
- [D-3] CPU-only brev box (`cpu-e2.4vcpu-16gb`) for live gating; teardown required
  (`brev delete` + `brev ls` verification). Matches GGML `gpu:false`.
- [D-4] Keep `LLAMACPP+GGML` build conflict (`BackendRegistry.cmake:147-149`).
  No registry/CMake contract change in this packet.
- [D-5] Buffer allocation failure is fatal. The current warn-and-continue
  (`GGMLInfer.cpp:101-106`) hides broken graphs.

## Assumptions

- [A-1] Pinned `GGML_VERSION=v0.11.0` headers expose everything the loader needs
  (`ggml.h`, `ggml-backend.h`, CPU backend). Confirm by compile probe.
- [A-2] The ONNX→GGML converter can be fixed to write real weights in a
  documented layout, or replaced by a minimal documented binary format the C++
  loader and the Python writer agree on.
- [A-3] ResNet18-float reference logits (ORT or ONNX) exist for golden tolerance.

## Open Questions

- [Q-1] Exact weight file layout: real GGUF vs minimal custom header?
  Recommendation: smallest documented layout both sides implement; no new SDK.
  Owner: implementer, must be recorded in validation before merge.
- [Q-2] Parity bar (Phase 2): top-5 class agreement + max-abs-logit-diff.
  ADOPTED 2026-11-13: tolerance **max-abs-diff ≤ 1e-3 with exact top-5
  agreement**, measured 6.38e-06 (gray) / 4.59e-06 (zeros) — ~150x inside.
  Reference: stock onnxruntime 1.32 venv on `resnet18-v1-7.onnx`
  (`scripts/ggml_ort_reference.py`).

## Requirements

- [R-1] `load_model` parses real model bytes; missing/corrupt file fails with
  the path in the message. No fixed-graph-near-empty-file acceptance.
- [R-2] Graph is the full ResNet18 topology built from loaded weights:
  conv stem → 8 residual blocks with skips → global average pool → FC head.
  BN folded exactly at load ([D-7]); no orphan tensors. Replaces the Phase 1
  head-only graph (scope note above).
- [R-3] `get_infer_results` returns computed outputs (non-zero, finite,
  deterministic for a fixed input); never the hardcoded zeros vector.
- [R-4] Shape contract stays explicit: single 4D input, exact byte-size check;
  violations fail with expected-vs-got.
- [R-5] `use_gpu=true` throws at load (actionable, names the request); never
  silently runs CPU.
- [R-6] Buffer allocation failure throws; no warn-and-continue path.
- [R-7] Tests: real-model golden + missing-file + bad-size + multi-input;
  mock-only passes do not count as loader evidence.
- [R-8] Dockerfile model stage + converter + `docs/backends.yaml` agree on the
  artifact the loader reads; `gen_backend_docs.py --check` passes.
- [R-9] Public C++ API / C ABI / plugin ABI unchanged (symbol + layout checks).
- [R-10] Live brev gate on `cpu-e2.4vcpu-16gb` + teardown verified (`brev ls`
  empty); no orphan instance.

## Compatibility Contract

Legacy `setup_inference_engine(model_path, use_gpu, batch_size, input_sizes)`
keeps its signature. Behavior change is intentional and narrow: `use_gpu=true`
now fails instead of silently running CPU, and a placeholder `.ggml` that used
to "load" now fails unless it carries real weights. Callers passing
`use_gpu=false` with a real artifact get real outputs where they got zeros.
